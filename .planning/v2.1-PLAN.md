# godot-mcp — Full Project Review: Fixes, Hardening, Infra, Docs, Features

## Context

The v2.0 milestone is complete and audited PASSED, but a 3-agent fan-out review (source architecture, test/build health, planning state) found: silent false-success bugs in core scene tools, a GDScript injection vector, near-worthless path validation guarding 65 tools, a packaging bug that disables 3 runtime tools in installed builds, a 10k-line test suite with no `npm test` script or CI, and heavy documentation/planning drift (README documents ~12 of 65 tools; ROADMAP contradicts reality). User chose full scope: all four remediation buckets plus a new-features track.

Work is organized as five tracks, ordered so correctness fixes land before refactors, and refactors before docs that describe them.

---

## Track A — Critical bugs + security (first)

Key design finding: the silently-broken legacy ops (modify_node_property, remove_node, attach_script, save_scene, load_sprite, export_mesh_library, create_scene, add_node, get_uid, resave_resources) **don't print failure JSON at all** — they `log_error()` to stderr + `quit(1)`, and `executeOperation` (godot.ts:239-257) discards the exit code. Newer ops (~24) do print `{"success":...}` JSON. So the verdict must be three-tier: trailing JSON (authoritative) → exit code ≠ 0 → stderr `[ERROR]`/`Failed to` marker. All 15 tool-test files mock `../src/godot.js` with closed factories, so each module migrates **in lockstep with its test file**.

### A-Step 0. Foundations in src/godot.ts (additive, zero test fallout)
- Debug gate: `GODOT_DEBUG_MODE = process.env.GODOT_DEBUG === 'true'` (godot.ts:24; removes `--debug-godot` flood, the `res://godot_mcp_test_write.tmp` write into user projects, and the PATH/HOME/USER env dump from godot_operations.gd:255-300).
- `executeOperation` gains `exitCode: number | null` in its return (additive; existing destructuring/mocks unaffected).
- Export pure `parseOperationOutput(stdout, stderr, exitCode): OperationResult` ({ok, error?, data?, stdout, stderr, exitCode}) — scan stdout last→first for a JSON line containing `success`/`error`; verdict tiers as above. Unit-testable with zero mocks → new tests/run-operation.test.ts (~15 cases incl. debug-noise interleaving, warnings-on-stderr-but-exit-0 → ok).
- Export `runOperation(ctx, projectPath, operation, params)` wrapping both.
- Harden `validatePath` in place (same signature → mocks unaffected): non-string/empty, null byte, `..`.
- New `resolveWithinProject(projectRoot, relPath): string | null`: resolve, realpath the root, containment via `relative()` check, realpath+recheck when the candidate exists (symlink escape); works for not-yet-existing output paths.
- New src/tools/common.ts `ensureProject(projectPath)`: validatePath + project.godot existence → standard toolError or null. Collapses the ~54 duplicated preambles; lives outside godot.ts so closed mock factories don't break, and per-file `vi.mock('fs')`/`vi.mock('../src/errors.js')` control it for free.

### A-Step 1. GDScript contract (src/scripts/godot_operations.gd)
- Add `fail(message)` helper: print `{"success":false,"error":...}` JSON + stderr `[ERROR]` + `quit(1)`. Convert the 10 legacy ops' failure paths to it; add trailing success JSON to their success paths. Exit-code tier remains as a net for missed paths.

### A-Step 2. Migrate tool modules to runOperation (module + test file in pairs; suite green after each commit)
1. scene.ts + scene-tools.test.ts (7 call sites — worst silent-false-success offenders).
2. uid.ts (no dedicated tests), resource.ts, script.ts + their test files.
3. `[ERROR]`-heuristic family: composition.ts, config.ts, animation.ts, shader.ts, tilemap.ts + 5 test files (26 sites, mechanical).
4. project.ts, scaffold.ts (currently ignores errors at :130-140), testing.ts, export.ts — export's `--export-release` path uses execGodot with no JSON contract; keep its bespoke stderr list there, migrate only its executeOperation call.
- Per-module transform: `const r = await runOperation(...); if (!r.ok) return toolError(\`Failed to X: ${r.error}\`, [existing suggestions])`. Test transform: add `runOperation: vi.fn()` to the godot.js mock factory; replace stderr-substring stubs with `{ok:false, error:...}` / `{ok:true, data:...}` stubs.

### A-Step 3. Path hardening rollout (one sweep commit after Step 2)
- Route secondary project-relative params through `resolveWithinProject`: scene_path, new_path, texture_path, output_path, script_path, shader_path, material_path, animation_path, library_path, tileset_path, resource_path, test_path, child_scene_path, scaffold target/output dirs. (node_path params are scene-graph paths, not FS — skip.)
- src/resources/godot-resources.ts:93-139 arbitrary-read fix: throw when no project resolves (currently falls through to reading the raw decoded path — worst hole); containment-check via resolveWithinProject; optionally enforce .tscn/.gd extension. Check resource-registration.test.ts expectations.
- New tests for resolveWithinProject + ensureProject (null byte, `..`, absolute escape, symlink, nonexistent output path).

### A-Step 4. GDScript injection fix (editor.ts:374-414)
- New static src/scripts/resize_image.gd reading `image_path, width, height` from positional argv after `--script` (same pattern as godot_operations.gd:14-36). `resizeScreenshot` spawns it directly — no temp file, no interpolation. Script path derived from `dirname(ctx.operationsScriptPath)`.

### A-Step 5. Small correctness fixes (one commit)
- runtime.ts: replace pollForResult with `triggerAndPoll(projectPath, command, params)` — delete stale output **then** write trigger, poll, parse, clean up; update 3 call sites (:122,:189,:259). Fixes the race and dedupes the trigger-write blocks. Also correct the STATE.md decision-log entry that claims the opposite ordering.
- restart_project (runtime.ts:299-390): ensureProject check + try/catch + exit/error handlers clearing ctx.activeProcess (mirror run_project, editor.ts:90-185).
- scripts/build.js: `fs.copySync(src/scripts → build/scripts)` — ships runtime_helper.gd (currently missing → 3 tools dead in installed packages) and resize_image.gd automatically.
- Version single-sourcing: package.json → 0.2.0; index.ts:31 reads it via `createRequire(import.meta.url)('../package.json').version` (works from src/ and build/). Check sdk-version.test.ts for the literal.
- LSP hardening (src/lsp/client.ts:56-81,186-199): request timeout + reject pendingRequests on close; guard `JSON.parse` in the data handler (malformed frame currently crashes the whole server).
- Escape strings in tscn-writer (src/parsers/tscn-writer.ts:42-43,61,103); validate node names/types against `[A-Za-z_][A-Za-z0-9_]*`.

## Track E — New features: "Close the Loop" phase (v3.0 milestone)

Recommended top-3 slice (net +3 tools, −1 autoload; shares files, good wave structure):

### E1. Zero-setup runtime helpers (prerequisite; extends run_project/restart_project)
- Merge screenshot_helper.gd into runtime_helper.gd (screenshot becomes one more IPC command; deletes a redundant autoload + trigger channel).
- `run_project` gains `inject_helpers` (default true): copy helper .gd into `<project>/.godot/mcp/`, temporarily add the autoload entry to project.godot (reuse config.ts autoload write path), restore on stop_project/exit.
- Closes the v2.0 audit tech-debt item: today every runtime tool silently times out (5s) unless a human hand-installs autoloads.
- Files: src/tools/editor.ts, src/tools/runtime.ts, src/scripts/runtime_helper.gd, src/godot.ts.

### E2. Runtime interaction bridge (3 new tools: send_input, invoke_runtime, wait_for)
- Extend runtime_helper.gd's `match command` dispatcher with `send_input` (parameterized InputEventAction/Key/MouseButton via Input.parse_input_event), `call_method`/`set_property` (parameterized — honors the PROJECT.md no-arbitrary-code-execution decision), `check_condition`; register tools in runtime.ts reusing pollForResult().
- `wait_for`: server-side loop polling a condition spec (node_exists, property compare, group count, elapsed frames) with timeout — replaces guess-timing sleeps.
- This is the missing half of the agent loop: press "jump" → wait_for(player moved) → screenshot.

### E3. Structured runtime errors + incremental debug output (0 new tools; extends get_debug_output)
- Params: `since_line` cursor (today every call returns full history — token sink) and `format: 'structured'` — new src/parsers/godot-log-parser.ts grouping `SCRIPT ERROR:` / `at: (res://file.gd:LINE)` / push_error blocks into `{kind, message, script, line, stack[]}`.

### Follow-up "Comprehension" phase (backlog, not this plan's execution scope)
- `query_symbol` (1 tool, operation enum: hover/definition/references/documentSymbol) over the existing LSP client; shared `ensureLsp()` helper refactor.
- `search_project` (1 tool, pure TS via existing tscn/project parsers): nodes by type, signal connections, scene/script dependents, regex over scripts.
- Runtime perf snapshot as an extra IPC command; burst screenshots as stretch.

### Explicit non-goals (context budget / security)
DAP breakpoint debugging; arbitrary GDScript eval (PROJECT.md non-goal — parameterized invoke_runtime covers it); script edit/refactor tools (host agent edits files; MCP validates); per-operation LSP tools (consolidated into query_symbol); video capture; editor GUI remote control.
