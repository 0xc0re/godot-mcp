## Directory Purposes

**src/**
- Purpose: Source code written in TypeScript
- Contains: Single main server file + GDScript operations
- Key files: `index.ts` (server logic), `scripts/godot_operations.gd` (Godot operations)

**build/**
- Purpose: Compiled JavaScript output ready for execution
- Contains: Transpiled index.js and copied scripts
- Generated: Yes (by `npm run build`)
- Committed: No (in .gitignore, published to npm as-is)

**scripts/**
- Purpose: Build and development automation
- Contains: Post-build script for permissions and asset copying
- Key files: `build.js` (makes build/index.js executable, copies godot_operations.gd)

## Naming Conventions

**Files:**
- Entry point: `index.ts` (ES module)
- GDScript operations: `godot_operations.gd` (single operations file)
- Build script: `build.js` (lowercase, .js extension)
- Build output: `build/` directory mirrors source structure

**Directories:**
- Source: `src/` (lowercase, common convention)
- Build output: `build/` (lowercase)
- Build tools: `scripts/` (lowercase)
- Hidden config: `.github/`, `.planning/` (leading dot)

**Functions/Methods:**
- Private methods: `private methodName()` with camelCase
- Public methods: `public async methodName()` with camelCase
- Handlers: `private async handleXxxTool()` - 12 handler methods follow this pattern
- Utility methods: `validatePath()`, `logDebug()`, `createErrorResponse()`

**Variables:**
- Private fields: `private fieldName: Type` with camelCase (e.g., `activeProcess`, `godotPath`)
- Local variables: camelCase (e.g., `projectPath`, `normalizedPath`)
- Constants: UPPER_SNAKE_CASE (e.g., `DEBUG_MODE`, `GODOT_DEBUG_MODE`)
- Parameters: camelCase (e.g., `projectPath`, `scenePath`)

**Types/Interfaces:**
- Interfaces: PascalCase (e.g., `GodotProcess`, `GodotServerConfig`, `OperationParams`)
- Records/Maps: Type annotations inline (e.g., `Map<string, boolean>`, `Record<string, string>`)

**Parameter Mappings:**
- MCP/JavaScript side: camelCase (e.g., `projectPath`, `scenePath`, `rootNodeType`)
- GDScript side: snake_case (e.g., `project_path`, `scene_path`, `root_node_type`)
- Conversion happens in `normalizeParameters()` and `convertCamelToSnakeCase()`

## Where to Add New Code

**New MCP Tool:**
1. Add tool definition in `setupToolHandlers()` (lines 656-917) within the tools array
   - Define name, description, inputSchema
2. Add case handler in `CallToolRequestSchema` switch statement (lines 920-957)
3. Implement `private async handleXxxTool(args: any)` method following existing patterns
4. Tool handler should:
   - Validate parameters with `validatePath()` if needed
   - Call `executeOperation()` with operation name and normalized params
   - Parse Godot output/errors from stdout/stderr
   - Return formatted response via `createErrorResponse()` or success object

**New Godot Operation (GDScript):**
1. Add operation function in `src/scripts/godot_operations.gd`
2. Implement function to take parameters and produce stdout output
3. Register in TypeScript handler via new `executeOperation()` call
4. Update tool definition in setupToolHandlers() if exposing as new MCP tool

**Utility Functions:**
- Shared path validation: Add to `validatePath()` or extend `isValidGodotPath()`
- Parameter handling: Extend `parameterMappings` for new camelCase↔snake_case conversions
- Error handling: Use `createErrorResponse()` with contextual solutions

**Configuration:**
- Runtime config: Extend `GodotServerConfig` interface for new constructor options
- Environment variables: Detect in `detectGodotPath()` or add new detection logic
- Debug flags: Extend global DEBUG_MODE checks or add handler-specific flags

## Special Directories

**build/**
- Purpose: Output directory for compiled TypeScript
- Generated: Yes, by `tsc` during `npm run build`
- Committed: No (.gitignore excludes it)
- Usage: Published to npm and executed as the main entry point
- Shebang: `#!/usr/bin/env node` added by build.js

**.planning/codebase/**
- Purpose: GSD codebase analysis documents (ARCHITECTURE.md, STRUCTURE.md, etc.)
- Generated: No (manually created by GSD analyzer)
- Committed: Yes (tracked in git)
- Usage: Reference for code generation and modification tasks

**src/scripts/**
- Purpose: Store GDScript files that execute Godot operations
- Committed: Yes (contains single `godot_operations.gd`)
- Special handling: Copied to `build/scripts/` by `scripts/build.js` during build
- Execution: Referenced via absolute path from compiled TypeScript at runtime
