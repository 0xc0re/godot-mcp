<objective>
Build the LSP client and get_diagnostics MCP tool that connects to Godot's language server over TCP to retrieve GDScript diagnostics (syntax errors, type warnings, undefined variables).

Purpose: This gives the AI real-time, type-aware feedback on GDScript code — far richer than the parse-only validation from validate_scripts (which only catches syntax errors). The LSP provides semantic analysis including type mismatches and undefined references.

Output: `src/lsp/client.ts` (TCP client), `src/tools/diagnostics.ts` (MCP tool), updated `src/index.ts` (registration + shutdown), updated `src/types.ts` (optional LSP fields on ServerContext), and tests for both.
</objective>

    - LspClient.connect(port) establishes TCP connection and completes LSP initialize handshake
    - LspClient.connect(port) rejects with descriptive error on ECONNREFUSED
    - LspClient.getDiagnostics(filePath, fileContent) sends didOpen notification and collects publishDiagnostics notifications with 5s timeout
    - LspClient.getDiagnostics returns array of diagnostic objects with range, severity, message
    - LspClient.disconnect() closes TCP socket gracefully
    - LspClient handles partial TCP messages via buffer accumulation (uses parseMessages remainder)
  </behavior>
  <action>
    1. Add optional LSP fields to `src/types.ts` ServerContext:
       ```typescript
       export interface ServerContext {
         // ... existing fields ...
         lspClient?: import('./lsp/client.js').LspClient;
         lspProcess?: ChildProcess;
       }
       ```

    2. Create `src/lsp/client.ts` with class `LspClient`:
       - Constructor: no args, initializes internal state (socket: net.Socket | null, buffer: Buffer, nextId: number, pending responses map, diagnostic listeners)
       - `async connect(port: number, host?: string): Promise<void>`:
         a. Create net.Socket, connect to port/host (default 'localhost')
         b. Set up `data` event handler that accumulates buffer, calls parseMessages, dispatches: responses to pending map by id, notifications to listeners by method
         c. Wait for socket 'connect' event
         d. Send `initialize` request (jsonrpc 2.0, id: nextId++, method: 'initialize', params with processId, capabilities.textDocument.publishDiagnostics.relatedInformation: true, rootUri)
         e. Wait for initialize response (via pending map Promise)
         f. Send `initialized` notification (no id, method: 'initialized', params: {})
       - `async getDiagnostics(filePath: string, fileContent: string): Promise<Diagnostic[]>`:
         a. Send `textDocument/didOpen` notification with uri: `file://${filePath}`, languageId: 'gdscript', version: 1, text: fileContent
         b. Listen for `textDocument/publishDiagnostics` notification matching the file URI
         c. Wait with 5s timeout; resolve with diagnostics array on first matching notification
         d. Return array of `{ range: { start: {line, character}, end: {line, character} }, severity: number, message: string, source?: string }`
       - `disconnect(): void`:
         a. Send `shutdown` request, then `exit` notification
         b. Destroy socket
       - Private `sendRequest(method, params)`: returns Promise resolved when response arrives
       - Private `sendNotification(method, params)`: fire-and-forget

    3. Create `tests/lsp-client.test.ts`:
       - Mock `net.Socket` using vi.mock('net')
       - Test: connect sends initialize request with correct params
       - Test: connect rejects on socket error event with ECONNREFUSED
       - Test: getDiagnostics sends didOpen and resolves when publishDiagnostics arrives
       - Test: getDiagnostics times out after 5s with empty array if no diagnostics received
       - Test: disconnect destroys socket

    Use `import { encodeMessage, parseMessages } from './protocol.js'` from Plan 01.
