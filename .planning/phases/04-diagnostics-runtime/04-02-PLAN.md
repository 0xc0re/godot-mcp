<objective>
Implement the capture_screenshot MCP tool that captures a screenshot of the running Godot game and returns it as a base64-encoded PNG for AI visual inspection.

Purpose: This enables an AI to visually inspect a running Godot game, closing the feedback loop between code changes and visual results. The tool uses a GDScript autoload injected into the game process that monitors a trigger file at a fixed project-relative path to capture the viewport on demand.

Output: `src/scripts/screenshot_helper.gd` (autoload script), updated `src/tools/editor.ts` (new capture_screenshot tool), and `tests/screenshot-tools.test.ts`.
</objective>

  <name>Task 1: Create screenshot helper GDScript and capture_screenshot tool</name>
  <files>src/scripts/screenshot_helper.gd, src/tools/editor.ts, tests/screenshot-tools.test.ts</files>
  <behavior>
    - capture_screenshot returns toolError when ctx.activeProcess is null (no game running)
    - capture_screenshot returns toolError when screenshot file is not produced within timeout
    - capture_screenshot returns MCP image content with type: 'image', mimeType: 'image/png', and base64 data when screenshot succeeds
    - capture_screenshot writes a trigger file at {project_path}/.godot/screenshot_trigger
    - capture_screenshot reads the resulting PNG from {project_path}/.godot/screenshot.png and returns it as base64
    - capture_screenshot resizes images exceeding 1MB before base64 encoding
  </behavior>
  <action>
    DESIGN: Fixed project-relative paths for screenshot coordination. The GDScript autoload
    polls `{project_path}/.godot/screenshot_trigger` and writes output to
    `{project_path}/.godot/screenshot.png`. No CLI args are needed -- the .godot/ directory
    is always present in any Godot project that has been opened in the editor. This avoids
    needing to modify run_project and works with any running game that has the autoload.

    1. Create `src/scripts/screenshot_helper.gd`:
       - Extends Node, designed as an autoload
       - Define constants at top of script:
         ```gdscript
         const TRIGGER_PATH := "res://.godot/screenshot_trigger"
         const OUTPUT_PATH := "res://.godot/screenshot.png"
         const POLL_INTERVAL := 0.5
         ```
       - In `_ready()`: initialize a timer variable `_elapsed = 0.0`. No CLI arg parsing needed.
       - In `_process(delta)`: accumulate delta into _elapsed; when _elapsed >= POLL_INTERVAL,
         reset _elapsed and check FileAccess.file_exists(TRIGGER_PATH)
       - When trigger file detected:
         a. Delete trigger file via DirAccess.remove_absolute(ProjectSettings.globalize_path(TRIGGER_PATH))
         b. Await RenderingServer.frame_post_draw signal
         c. Capture viewport: `var image = get_viewport().get_texture().get_image()`
         d. Do NOT call `flip_y()` (not needed in Godot 4.x per research)
         e. Save PNG: `image.save_png(ProjectSettings.globalize_path(OUTPUT_PATH))`

    2. Modify `src/tools/editor.ts` to add `capture_screenshot` tool:
       - Input schema: `project_path` (string, required) -- the project directory
       - Implementation:
         a. Validate project_path with validatePath()
         b. Check `ctx.activeProcess` is not null, return toolError if no game running
         c. Define fixed paths:
            `const triggerPath = join(project_path, '.godot', 'screenshot_trigger')`
            `const outputPath = join(project_path, '.godot', 'screenshot.png')`
         d. Write the trigger file (empty file, `fs.writeFileSync(triggerPath, '')`)
         e. Poll for the output PNG file with 100ms intervals, timeout after 5 seconds
         f. Read the PNG file as a Buffer
         g. Check file size: if > 800KB (conservative threshold under 1MB limit),
            resize using Godot headless: spawn `ctx.godotPath` with a one-liner GDScript
            that loads the image, resizes to 960x540, and re-saves:
            `spawn(ctx.godotPath, ['--headless', '--script', '-'], { input: resizeScript })`
            where resizeScript is:
            ```gdscript
            extends SceneTree
            func _init():
                var img = Image.load_from_file("{outputPath}")
                img.resize(960, 540, Image.INTERPOLATE_BILINEAR)
                img.save_png("{outputPath}")
                quit()
            ```
            Alternatively, if spawning Godot for resize is too heavy, use a simpler approach:
            just log a warning in the tool response text noting the image may be large.
            PREFERRED: Use the Godot resize approach since we already have ctx.godotPath.
            Re-read the file after resize.
         h. Convert to base64: `Buffer.from(readFileSync(outputPath)).toString('base64')`
         i. Clean up: delete trigger file if still present, delete output PNG
         j. Return MCP image content: `{ content: [{ type: 'image', data: base64, mimeType: 'image/png' }] }`
       - Tool description should note that `ScreenshotHelper` must be added as an autoload
         to the Godot project for capture_screenshot to work.

    3. Write `tests/screenshot-tools.test.ts`:
       - Mock fs.writeFileSync, fs.readFileSync, fs.existsSync, fs.unlinkSync, child_process.spawn
       - Test: no active process returns error
       - Test: screenshot file not produced within timeout returns error
       - Test: successful capture returns image content with correct structure
       - Test: large file triggers resize (mock file size > 800KB)
       - Follow existing test patterns from tests/scene-tools.test.ts
