  <behavior>
    ## parseScene(content: string): ParsedScene

    Given a .tscn file content string, returns a ParsedScene object:

    - Parses `[gd_scene ...]` header: extracts format, uid, load_steps
    - Parses `[ext_resource ...]` sections: extracts type, uid, path, id for each
    - Parses `[sub_resource ...]` sections: extracts type, id, and all property key-value pairs
    - Parses `[node ...]` sections: extracts name, type, parent, instance, and all property key-value pairs
    - Parses `[connection ...]` sections: extracts signal, from, to, method
    - Properties are stored as raw string values (no type conversion -- that is Godot's job)
    - Root node has no parent attribute; children have parent="." for direct children of root
    - Deeper children have parent="NodeA/NodeB" style paths

    Test cases:
    - Minimal scene (just header + root node) -> ParsedScene with 1 node, empty arrays for rest
    - Scene with ext_resources -> extResources array populated with type, uid, path, id
    - Scene with sub_resources -> subResources array with type, id, properties
    - Scene with node hierarchy (root + 3 children at different depths) -> correct parent refs
    - Scene with connections -> connections array with signal, from, to, method
    - Scene with node properties (transform, position, etc.) -> properties Record populated
    - Empty string -> ParsedScene with empty arrays and defaults

    ## parseResource(content: string): ParsedResource

    Given a .tres file content string, returns a ParsedResource object:

    - Parses `[gd_resource ...]` header: extracts type, format, uid, load_steps
    - Parses `[ext_resource ...]` sections (same as scene)
    - Parses `[sub_resource ...]` sections (same as scene)
    - Parses `[resource]` section: all properties of the main resource
    - Properties stored as raw strings

    Test cases:
    - Minimal resource (header + resource section with one property) -> type + property
    - Resource with ext_resources -> extResources populated
    - Resource with sub_resources -> subResources populated
    - Resource with multiple properties -> all properties in Record
    - Empty string -> ParsedResource with defaults

    ## Parser internals

    - parseSectionHeader(line) parses `[type key=val key="val" ...]` into {type, attributes}
    - parsePropertyLine(line) parses `key = value` into [key, value] tuple
    - Multi-line property values (arrays, dictionaries spanning lines) are concatenated
  </behavior>
  <implementation>
    1. Create src/parsers/tscn-types.ts with all interfaces:
       - ParsedScene: { format, uid?, loadSteps?, extResources, subResources, nodes, connections }
       - ParsedResource: { type, format, uid?, loadSteps?, extResources, subResources, properties }
       - SceneNode: { name, type?, parent?, instance?, properties: Record<string, string> }
       - ExtResource: { type, uid?, path, id }
       - SubResource: { type, id, properties: Record<string, string> }
       - Connection: { signal, from, to, method, flags? }

    2. Create src/parsers/tscn-parser.ts:
       - parseSectionHeader(line): Parse bracketed section headers like [node name="X" type="Y" parent="."]
         using regex: /^\[(\w+)(.*?)?\]$/ then parse key=val pairs with /(\w+)=(?:"([^"]*?)"|(\S+))/g
       - parsePropertyLine(line): Split on first ' = ' to get [key, value]
       - parseScene(content): Split content by lines, iterate tracking current section,
         build arrays of ext_resources, sub_resources, nodes, connections based on section type
       - parseResource(content): Same approach but looks for gd_resource header and [resource] section
       - Handle multi-line values: detect when a property value has unmatched brackets/parens and
         accumulate subsequent lines until balanced

    3. Create test fixtures:
       - tests/fixtures/sample.tscn: A Godot 4.x scene with header, 2 ext_resources,
         1 sub_resource, root + 3 child nodes at varying depths, 1 connection, nodes with
         transform/position properties
       - tests/fixtures/sample.tres: A StandardMaterial3D resource with header, properties
         including albedo_color = Color(...), and a sub_resource
  </implementation>
</feature>
