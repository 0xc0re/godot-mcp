Rewrite src/index.ts to use the new SDK API while keeping ALL existing tool logic. This is an in-place migration of the monolith -- the modular refactor happens in Plan 02.

**Step-by-step migration in src/index.ts:**

1. Replace imports:
   - Remove: `Server` from `@modelcontextprotocol/sdk/server/index.js`
   - Remove: `CallToolRequestSchema`, `ErrorCode`, `ListToolsRequestSchema`, `McpError` from `@modelcontextprotocol/sdk/types.js`
   - Add: `McpServer` from `@modelcontextprotocol/sdk/server/mcp.js`
   - Add: `z` from `zod`
   - Keep: `StdioServerTransport` from `@modelcontextprotocol/sdk/server/stdio.js`

2. Replace GodotServer class constructor's server creation:
   - Old: `this.server = new Server({ name: 'godot-mcp', version: '0.1.1' }, { capabilities: { tools: {} } })`
   - New: `this.server = new McpServer({ name: 'godot-mcp', version: '0.2.0' }, { capabilities: { tools: {} } })`

3. Replace `setupToolHandlers()` method:
   - Remove the `ListToolsRequestSchema` handler (McpServer handles tool listing internally)
   - Remove the `CallToolRequestSchema` handler with the switch statement (McpServer handles dispatch internally)
   - Replace with individual `this.server.registerTool()` calls for each of the 14 tools

4. For each tool registration, convert the hand-written JSON schema to Zod:
   - Use `z.string()` for string params, `z.boolean().optional()` for optional booleans, etc.
   - Use `.describe()` on each Zod field to preserve the description from the original JSON schema
   - Use snake_case keys in the Zod schema (matching what GDScript expects), eliminating the need for normalizeParameters/convertCamelToSnakeCase

5. Example migration for one tool (launch_editor):
   ```typescript
   this.server.registerTool(
     'launch_editor',
     {
       title: 'Launch Editor',
       description: 'Launch the Godot editor for a specific project',
       inputSchema: {
         project_path: z.string().describe('Path to the Godot project directory'),
       },
     },
     async ({ project_path }) => {
       return this.handleLaunchEditor({ projectPath: project_path });
     }
   );
   ```

6. Keep ALL handler methods (handleLaunchEditor, handleRunProject, etc.) intact. The registerTool callbacks should call into existing handlers, mapping snake_case args to what the handlers expect. This preserves all existing logic.

7. Remove `normalizeParameters()` and `convertCamelToSnakeCase()` methods since Zod schemas now use snake_case directly. BUT keep the internal parameter conversion in `executeOperation()` since that function still needs to send snake_case to GDScript -- review that it already does this correctly.

8. Update the server type in the class from `Server` to `McpServer`.

9. Ensure ALL registerTool() calls happen in the constructor (before `run()` calls `connect()`), matching the pitfall from research: "registerTool() Must Be Called Before connect()".

10. Verify the build compiles: `npm run build`

11. Update tests/tool-registration.test.ts:
   - Import and instantiate GodotServer (or test at module level)
   - Verify that `npx vitest run` passes

**IMPORTANT:** Do NOT refactor into modules yet. Keep everything in src/index.ts. The modular refactor is Plan 02's scope. This task is ONLY about migrating the SDK API.
