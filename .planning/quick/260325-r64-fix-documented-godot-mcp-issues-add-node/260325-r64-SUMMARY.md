# Quick Task 260325-r64: Fix Documented godot-mcp Issues (add_node + export) Summary

TypeScript-native .tscn writer for add_node (avoids GDScript autoload corruption) plus stderr error detection for export_project.

## Tasks Completed

### Task 1: Create tscn-writer and rewrite add_node to use TypeScript text manipulation
- **Commit:** 264b60e
- **What:** Created `src/parsers/tscn-writer.ts` with `addNodeToScene()` function that manipulates .tscn text content directly. Rewrote `add_node` handler in `scene.ts` to use `readFileSync` -> `addNodeToScene` -> `writeFileSync` instead of `executeOperation`.
- **Why:** The GDScript `load()` -> `instantiate()` -> `pack()` cycle in the old add_node triggers script execution in headless mode. When root scripts reference autoload singletons (which don't exist headless), this corrupts the scene. TypeScript text manipulation never executes any GDScript.
- **Key details:**
  - Parent path mapping: "root" -> parent=".", "root/X" -> parent="X", "root/X/Y" -> parent="X/Y"
  - Property serialization: Vector2/Vector3/Color objects, booleans, numbers, quoted strings
  - New nodes inserted before [connection] sections (required .tscn ordering)
  - 14 tscn-writer unit tests + 6 add_node handler tests (20 total)
  - GDScript `add_node` function in `godot_operations.gd` left intact as potential fallback

### Task 2: Fix export_project to check stderr for error strings
- **Commit:** c304dad
- **What:** Changed `const { stdout }` to `const { stdout, stderr }` in export_project handler. Added stderr checks for ERROR, Cannot open file, Failed to, and Invalid patterns.
- **Why:** Godot may emit error strings to stderr even with exit code 0. Previously only stdout was checked.
- **Key details:**
  - 4 new tests covering stderr error detection + clean stderr success case
  - All 23 export tests pass
